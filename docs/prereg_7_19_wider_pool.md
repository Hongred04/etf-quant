# 试验预注册 7.19 — 扩大候选池（260 → 400 / 700）

> 跑之前写入，跑完不改。hash 冻结在 `data/prereg_7_19_wider_pool.sha256`。

- 登记时间：2026-11-01
- 来由：`docs/model_self_check.md` 1.1 指出池成员由今日流动性决定，且 2019 年
  池内仅 39 只可用（15%）。策略只能从"今天成交额前 260"里选，等于把一个
  人为收窄的空间当成全部机会。
- 与 7.x 其他试验的区别：**不改任何策略参数**（top_n=3、freq=5、buffer=2、
  gate、score_mode 全部不动），只换候选池。这是"扩大搜索空间"，不是"在同一空间里调参"。

## 一、事实基础（跑之前已核实）

| 项 | 值 |
|---|---|
| 全市场 ETF 快照 | 945 只 |
| 成交额 > 2000 万（现有 `min_avg_amount`） | **721 只** |
| 现有池 | 259 只（`max_size=260`） |

## 二、变体（固定 2 个）

| 代号 | 池规模 | 生成方式 |
|---|---|---|
| **V0** | 259（现状） | `data/etf_pool.csv`，基线 |
| **V1** | 400 | `build_universe(max_size=400)` |
| **V2** | 721 | `build_universe(max_size=721)`，即全部满足流动性门槛的标的 |

三个池都用同一个 `min_avg_amount=2e7`、`min_hist_days=250`、剔除货币。
**V0 ⊂ V1 ⊂ V2**（按成交额排序后截断），确保是严格的超集比较。

## 三、判据（预先固定）

主判据（卡玛）：
- **有效**：V1 或 V2 的卡玛 ≥ V0 + 0.03，**且** CAGR ≥ V0 − 0.5pp。
- **部分有效**：卡玛提升 ≥ 0.03 但 CAGR 下降 > 0.5pp（用回撤换收益，需单独说明）。
- **否**：卡玛提升 < 0.03。

代价判据（必查，防"扩池=降质量"）：
- 2x 成本下（0.20%/边）V1/V2 的卡玛不得低于 V0 在 1x 成本下的 **80%**。
  理由：新增标的多为小规模 ETF，冲击成本更高，如果扩池的收益被成本吃掉，等于没扩。

辅助观察（不作判据）：
- 各年度的"实际可用标的数"变化——扩池若只增加近年上市标的，
  则 2019-2021 段不会有任何改善，这一点必须如实写明。

## 四、不做的事

- 不新增策略参数，不搜索 top_n / freq / buffer（那些已在 7.5 冻结）。
- 不因结果不好看而回头调整池的构成规则（如"只保留行业 ETF"）。
- 不把三个变体的最好结果当结论；V1 与 V2 都要报。

## 五、已知风险

- **成本反向**：池子越大，越可能选到流动性差的标的，滑点上升。
  这是判据里"2x 成本"那一项要防的。
- **前视偏差不会因扩池而消除**：新池仍是按今日快照筛的，只是筛得宽一些。
  本试验只能缓解"空间被人为收窄"，不能修复"成员由今日决定"。
- **早期年份可能零改善**：若新增标的绝大多数 2022 年后才上市，
  2019-2021 段不会有变化，整体改善会被稀释。
