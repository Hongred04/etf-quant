# etf-quant — ETF 量化选股工具

面向 A 股 ETF 的量化选股与轮动回测工具。包含完整数据管道、因子库、四个可比策略、
事件驱动回测引擎、绩效归因与实验验证框架。

**核心结论**：基于全市场 260 只 ETF 的 20 日动量轮动 + 趋势闸门策略（TGAR），
在 2019-01-02 ~ 2026-10-29 的回测中取得年化 **17.3%**、最大回撤 **-28.9%**、
夏普 **0.69**、卡玛 **0.60**（基准沪深300 全收益：年化 7.1%、回撤 -44.7%、夏普 0.37）。

> **口径**：17.3% 是**样本内**上限——29 个变体在同一段历史上比过大小，"留下的那套最好"
> 本身带乐观偏差。扣掉"挑参数"的代价后，可对外引用的是 **11%~13%**，锚点来自
> 「每 6 个月重挑一次参数」的纯样本外年化（12.62%）。详见 [6.2](#62-这个数字该怎么读对外口径-1113) 与 7.5。

> 回测基于历史数据，不代表未来收益，不构成投资建议。

## 零点五、手机版（Android APK，独立运行）

`dist/etf-quant.apk`（0.50 MB，minSdk 24 / targetSdk 34，v1.5.0）。

**完全独立**，不需要电脑、不需要服务器：

| 环节 | 在哪完成 |
|---|---|
| 300 天历史日线（260 只） | 打包时写进 APK（1.1 MB） |
| 最新行情 | App 启动时直接向腾讯请求（5 个请求，约 1 秒） |
| 信号计算 | 手机本地，`js/engine.js` 重算，**16 ms** |
| 断网 | 显示上一次算好的结果，不报错 |

装了就能用。只要手机能上网（Wi-Fi 或流量都行），打开 App 就会自动拉最新行情、
重算信号；断网时显示缓存。**不再需要和电脑同一 Wi-Fi，也不需要在 App 里配任何地址。**

更新过程**不弹任何文字提示**，标题栏右侧只有一个圆环：请求时旋转、补齐时按比例推进、
完成变绿勾、失败变红叉（自动同步失败则静默消失）。失败原因记录在「更多 → 数据与计算」。

**盘中不落盘**：交易时段（9:30–15:00）快照给的是实时价，不是收盘价。
此时只更新下单表用的参考价，不写入当日 K 线，信号继续基于上一个完整收盘日，
界面标注「盘中 / 未收盘」。桌面端的下载脚本也做了同样的保护。

手机端不是桌面页面的缩放版，而是按移动端重新设计的五栏应用：
**概览 / 今日 / 持仓 / 验证 / 更多**，支持深浅双主题、左右滑动切页、术语点按弹层、原生剪贴板。

### 引擎移植与对拍

手机端的策略计算是 `etfquant/strategy.py` 里 `TrendGatedAdaptive` 的逐行移植。
为了确保不是"看起来差不多"，`scripts/verify_mobile_engine.py` 用同一份历史数据
分别跑 Python 与 JS，逐项比对 regime、敞口、持仓集合、单只权重：

```
5 个时点（最近 / 5 天前 / 20 天前 / 60 天前 / 120 天前）
regime、敞口、权重合计、单只权重最大差 = 0   全部 PASS
因子级抽查：候选的 R20 逐个一致            全部 PASS
```

`mobile/README.md` 记录了移植过程中三个必须对齐的细节（横截面缩尾的范围、
`min_periods`、`volume` 用 `fillna(0)` 而非 ffill）。

## 零点三、运行环境与故障排查

本项目依赖 `pandas` / `numpy`，装在**项目自带的虚拟环境** `.venv` 里。

### 为什么不装在全局 Python

Windows 上 `python` 命令经常指向 Microsoft Store 的占位符，或者 WorkBuddy 客户端的
托管解释器（`~/.workbuddy/binaries/python/versions/3.13.12` 其实是指向客户端资源目录的符号链接）。
后者在客户端更新/修复时会被重置，第三方包会被清空——表现出来就是**项目突然打不开**：

```
ModuleNotFoundError: No module named 'numpy'
```

装到 `.venv` 后，依赖跟着项目走，与全局环境、与客户端资源目录都无关。

### 正常启动

双击 **`打开界面.bat`**。脚本按此顺序找解释器：

1. 项目内 `.venv\Scripts\python.exe`（先验证能启动，拷到别处失效时会跳过）
2. WorkBuddy 托管解释器
3. `py -3` / PATH 上的 `python`（自动过滤 WindowsApps 占位符）
4. 常见安装路径

找到后先检查 `pandas`/`numpy` 是否可导入；缺失则自动执行
`pip install -r requirements.txt`，失败会给出中文原因并暂停窗口（不会一闪而过）。

### 常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| 窗口一闪而过 | Python 起不来或缺依赖 | 现在会停住并打印原因；看窗口里的 `[ERROR]` 行 |
| 提示 `No module named 'numpy'` | 用了被重置的全局/托管解释器 | 删掉 `.venv` 文件夹，重新双击 `打开界面.bat` 让它重建 |
| 提示 `Dependency install failed` | 连不上 pypi，或解释器本身损坏 | 检查网络；或手动执行 `.venv\Scripts\python.exe -m pip install -r requirements.txt` |
| 页面打开但数字不刷新 | 数据还是旧的 | 到「数据与维护」点「更新历史行情」，或改 `.venv` 里的数据后重跑脚本 |
| 端口被占用 | 已有一个实例在跑 | 脚本会自动换端口，以窗口里打印的地址为准 |

### 手动安装（可选）

```bash
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe server.py
```

## 二点四、数据自动更新

打开控制台时，前端先问一次 `/api/status`，判断本地数据是否落后于**最近一个已收盘交易日**：

| 情况 | 判定 | 处理 |
|---|---|---|
| 数据落后 | `data_date` < `expected_date` | 后台自动跑 `refresh`（更新行情 → 重跑回测 → 生成信号），跑完自动刷新页面 |
| 回测产物落后 | 行情已到最新，但权重表还停在旧日期 | 横幅提示「回测产物落后于行情」，一键重跑回测 |
| 已最新 | 两者一致 | 不打扰，侧栏显示「数据已是最新」 |

几个口径上的取舍：

1. **「应到哪天」优先看行情快照的时间戳**，不用日历推算。春节这类长假靠日历会误报「落后 7 个交易日」，而腾讯快照在假期会停在上一个交易日，天然可识别。
2. **盘中打开只会更新到上一个交易日**：今天的数据要到 15:00 收盘后才完整，不会把半天的行情当 K 线写进去。
3. **同一目标交易日只自动跑一次**。首发去重键是「今天 | 目标交易日」，所以盘中跑过之后，收盘后目标日推进会再允许自动跑一次，不需要手动点。
4. 自动更新失败（断网、脚本报错）不会反复重试，降级成横幅上的「立即更新」按钮，避免每次刷新都卡一次。
5. **当日 K 线是分批落库的，只到了一部分就整天丢弃**。收盘后腾讯按批补齐：2026-10-30 15:30 实测 260 只里只有 165 只有当日 bar（63%），傍晚才陆续补完。若把这半天写进缓存，面板会对余下标的 ffill 昨天收盘价——当天涨跌只由一部分标的贡献，横截面排名、波动率、量比同时失真，而且**全程不报错**。现在门槛是 80%（`datafeed.PARTIAL_DAY_MIN_COVERAGE`）：低于就整天丢弃、把已写入的那一天回写裁掉（否则下次运行时它满足 `last >= expected`，会被当成已是最新），并让 `refresh` 以退出码 3 中止。过 5~10 分钟重跑即可。

手动入口有两个：横幅右侧按钮，或「数据与维护 → 更新行情并重算（推荐）」。

## 二点五、我的持仓（实盘）

「我的持仓」记录**你自己**的份额与成本，和「回测持仓」不是一回事——后者是策略在历史回测里的模拟账户。

**入口**：桌面端左侧「我的持仓」；手机端「持仓 → 我的持仓」。

| 项 | 说明 |
|---|---|
| 存储位置 | 桌面端 `data/my_holdings.json`（原子写）；手机端 `localStorage: etfq-hold`（不随引擎升级清空） |
| 录入字段 | 代码、份额、成本价（摊薄成本）、买入日、备注 |
| 价格来源 | 桌面端：腾讯实时快照（20 秒缓存）→ 池快照 → 日线末尾；手机端：实时快照 → 内置日线末尾 |
| 浮动盈亏 | 市值 − 成本额。不含已实现盈亏，不扣手续费 |
| 今日盈亏 | 老仓按（现价 − 昨收）；**当日买入**按（现价 − 成本价），避免把买入前的行情算成自己的盈亏 |
| 仓位占比 | 市值 ÷ 总资产，总资产 = 持仓市值 + 可用现金 |
| 调仓建议 | 目标仓位取今日信号 weight，差额 < 2 个百分点或不足一手时判定「不动」 |

**一键建仓**：填一个金额，按今日清单的占比换算成整手（100 份向下取整），买不满的留现金，写进同一份持仓文件。

**已知限制**：

1. 只维护当前持仓快照，不记买卖流水，因此**没有已实现盈亏**，也没有历史成交复盘；
2. 建议按「仓位差 × 总资产」估算金额，未考虑手续费、滑点与最小价差；
3. 同日多次买入同一标的请自行合并成一个摊薄成本；
4. 「已持 N 个交易日」按 K 线根数计，不是自然日（09-21 到 10-27 是 21 个交易日 / 36 天）；
4. 池外标的（新上市、成交额不足）仍可录入，估值回落到日线缓存；连缓存都没有时会标「暂无行情」且**不计入合计**，避免用成本价顶替造成虚假市值。

## 二点六、实盘跟踪（信号归档）

「回测持仓」是引擎内部重算的结果，数据修订后会变；「实盘跟踪」记录的是**当时真实给出什么**，
两者不能互相替代。

| 项 | 说明 |
|---|---|
| 存储 | `data/signal_archive.csv`，一期一组 `(signal_date, code, weight, ref_price, source)` |
| 写入 | 每次「生成选股信号」自动追加，**同一信号日整体替换**，不会叠加 |
| 来源标记 | `live` = 当日真实输出；`backfill` = 事后回放（`scripts/backfill_archive.py`） |
| 纸上净值 | 复用 `Backtester`：次日开盘成交、双边 0.10% 成本，与主回测同一套记账 |
| 对照线 | 同区间、同成本下的策略调仓日目标，用来暴露"归档与引擎是否一致" |

**两条必须守住的口径**：

1. `backfill` **不得覆盖**同日期的 `live`——否则"当时的建议"会被事后重算悄悄改掉，
   复盘就失去意义；
2. 连续两期**目标权重完全相同**时只算一次调仓。用户每天点一次「生成信号」都会写一条归档，
   若原样喂给回测器，等于每天把组合拉回目标权重，凭空多出一笔策略里不存在的再平衡成本
   （实测压低纸上净值约 0.4 个百分点）。

页面：桌面端左侧「实盘跟踪」。

> **当前状态（2026-10-29）**：20 期归档（1 期真实 + 19 期回填），纸上净值与同期回测
> **偏差 0.000pp**。这条对照线原来的偏差是 −0.39pp，根因是"日更信号"与"5 日调仓"口径不一致
> ——每天跑一次就归档一条新目标，等于天天再平衡。信号钉回调仓日之后，偏差归零。

## 二点七、调仓日历（为什么清单不是每天变）

策略每 5 个交易日换一次仓，但行情每天都有。所以「信号日」和「调仓日」必须分开，
否则每天跑一次就会得到一份"新"清单——换手放大 3~5 倍，成本按比例增加，
而且与回测口径不符。

| 日期 | 含义 | 来源 |
|---|---|---|
| 调仓决策日 | 这一期目标权重是哪天收盘定的 | `last_rebalance()`：`≤ 数据截止日` 的最近一个调仓日 |
| 开盘买入日 | 次日开盘执行（T 日收盘定、T+1 开盘买） | 调仓日后第一个交易日 |
| 下次换仓日 | 同一网格再走 `rebalance_freq` 步 | 数据覆盖到时取真实交易日；否则按工作日估算并标注 |

界面对应五种状态（`server._signal_status()`，纯函数，10 项单测）：

| 状态 | 判定 | 提示 |
|---|---|---|
| `pending` 待执行 | 今天 < 买入日 | 「X 月 X 日开盘按这份清单买入」 |
| `exec_today` 今天买入 | 今天 = 买入日 | 标红：「今天开盘就要换仓」 |
| `holding` 持有中 | 买入日 < 今天 < 下次换仓日 | 「今天不需要操作」+ 还剩几个交易日 |
| `today` 今天换仓 | 今天 = 下次换仓日 | 标红：「收盘后更新行情重算，明天开盘换」 |
| `due` 已过期 | 今天 > 下次换仓日 | 标红：清单作废，必须重算 |

**调仓日提醒（可选）**：桌面「数据与维护 → 调仓日提醒」、手机「更多 → 设置 → 调仓日提醒」各有一个开关。
开启后只在 `exec_today` 与 `today` 这两天各提醒一次（每天最多一条），其余时间不打扰。
桌面走浏览器通知（需授权，被拒则退回页面内 toast）；手机走原生通知，Android 13+ 会申请
`POST_NOTIFICATIONS`，未授权时退化为 Toast。

不打开界面也能查：

```bash
python scripts/rebalance_status.py          # 今天该不该动手、下次哪天换
python scripts/rebalance_status.py --json   # 给脚本/Agent 解析
python scripts/rebalance_status.py --check  # 需要动手时退出码 0，否则 3
```

这个入口和界面共用 `etfquant/rebalance.py` 与 `server._signal_status()`，不存在第二套判定。

实现上只有 `etfquant/rebalance.py` 这一处判定（纯函数，11 项单测），
`run_signal.py` / `server.api_signal()` / 手机端引擎都调它，避免两端各写一遍相位逻辑。
手机端拿服务端给的 `reb_date` 当锚点，沿等步长网格往前推进到最新一根 K 线——
这样即使 App 又补进了几天行情，也仍然落在正确的调仓日上。

## 二点八、前向验证月报

7.5 节的结论是"继续调参的期望收益已低于过拟合风险，下一步只能看前向"。
前向这件事必须有人按月看一眼，否则归档了几十期也没人知道有没有跑偏。

```bash
python scripts/monthly_report.py                # 上月
python scripts/monthly_report.py --month 2026-10
python scripts/monthly_report.py --month 2026-10 --json   # 给脚本 / Agent 读
```

产物 `output/reports/monthly_<YYYY-MM>.md`，六节：跟踪概览（期数 / 纸上累计 / 同期回测 / 偏差）、
本月调仓（信号日 / 买入日 / 期间收益 / 持仓）、下一期、口径、**alpha 跟踪**、提示。

四个关键设计：

1. **偏差比收益重要**。纸上净值与同期回测的差值正常应≈0（两者用同一套 `Backtester` 与成本）；
   持续为负说明执行或归档走样，持续为正反而说明记账口径不一致——两种都写进「提示」。
2. **口径固定写一遍**。月报里每次都带"样本内上限 vs 对外预期"，避免看多了曲线就把它当承诺。
3. **收益要拆成"因子能解释的"和"解释不了的"**（第五节，`etfquant/alpha_track.py`）。
   残差 = 策略月收益 − (α/12 + Σβ·因子月收益)，β 取 7.10 的诊断结果并**冻结**。
   这一节的价值不在那个百分比，而在它**强制附带误差棒**：本策略月残差 σ≈5.7%，
   n 个月累计后的年化标准误是 12σ/√n —— 12 个月 20pp、36 个月 12pp。于是三条纪律：
   单月 |z|<2 不解读；**"证明 alpha 存在"需要约 200 个月（17 年）**；能及时抓到的只有
   |z|>3 的"断裂"（执行 / 记账 / 数据出问题）。**前向跟踪的用途是证伪，不是确认。**
4. **渲染是纯函数**（`etfquant.monthly.render_markdown`，11 项单测）。月初跑挂了很难发现，
   所以"没有调仓""净值点不足两个""口径数据缺失""alpha 块缺失"这些边界都在单测里固定住。

自动化：每月 1 日 09:00 生成一次并汇总到对话里（WorkBuddy 定时任务）。

## 三、数据来源

**腾讯财经公开行情接口**，无需 Token，无需 akshare / tushare。

| 用途 | 接口 | 约束 |
|---|---|---|
| ETF 全市场发现 | `qt.gtimg.cn/q=<codes>` | 批量 60 个/请求，60 个约 0.2 秒 |
| 日线行情（主） | `web.ifzq.gtimg.cn/appstock/app/fqkline/get` | 前复权，单次上限 640 根，按时间窗分段拼接 |
| 日线行情（备） | `proxy.finance.qq.com/ifzqgtimg/appstock/app/newfqkline/get` | 同上；参数只认 `count`，返回后再按区间裁剪 |

选择该数据源的原因：本机网络环境下东方财富、新浪行情接口不可直连，腾讯接口稳定可用。

**为什么是"两个入口"而不是"两个数据源"（2026-10-30 定案）**

那天跑 2015 压力测试时，把 260 只标的按**每月**一个窗口翻页，一口气发了近 5000 次请求，
`web.ifzq.gtimg.cn` 随即对**任何区间**返回 501（连当天的窗口也 501），只有快照域名还活着。
GitHub 上高星项目的做法印证了这一点：「腾讯 K 线单入口约 600 次后限流，已三入口轮换」。

于是改成：**同厂商、不同域名，按请求轮换 + 失败冷却 5 分钟**。
不用东财/新浪/同花顺做备份，理由是**复权因子**——不同厂商的 qfq 基准不同，
混进来会让缓存拼接处出现跳空，而跳空会被当成真实收益，且不会报错。
两个腾讯入口的 `qfqday` 已逐位比对：开高低收最大绝对差 **0.000000**、成交量比 **1.0000**，
所以可以安全互换。备用入口只认 `count`（不认 `start`），返回后在 `fetch_kline_window`
里统一裁剪，保证两个入口在同一窗口上的输出完全一致。

副作用是好的：日常更新现在把请求分摊到两个入口，单入口的 600 次上限被推后一倍。

**口径与偏差**：

- 价格为前复权，收益序列连续。
- **幸存者偏差**：标的池取自当前在市 ETF，期间清盘的基金未纳入。
- 成交额用 `收盘价 × 成交量(手) × 100` 近似。

## 五、策略：TGAR 趋势闸门自适应轮动

### 5.1 五层结构

**第 1 层｜市场状态闸门（买多少）**
基准沪深300ETF 三项条件加权：`>MA200 +0.4`、`>MA60 +0.3`、`R20>0 +0.3`，得 regime ∈ [0,1]。
映射**权益**敞口（两档）：`≥0.7 → 100%`，`<0.7 → 50%`（不空仓）。
未用敞口配 20 日动量最强的债券 ETF。

> **「半仓」的口径**：指权益（股票/商品/跨境）占一半，另一半买入债券 ETF，
> 账户始终是满仓，**不会留一半现金**。界面上用「权益 / 债券 / 现金」三段条展示，
> 三块合计 100%；接口字段为 `signal.position.{equity,bond,cash}`。

**第 2 层｜标的初筛（能不能买）**
上市满 250 交易日 + 20 日均成交额 ≥ 2000 万 + 收盘 > MA60 + 量比(5/60) < 3.0。

**第 3 层｜横截面打分（买哪只）**
`score = z(R20)`，R20 剔除最近 5 个交易日（规避短期反转），全池横截面标准化 + 2%/98% 缩尾。

**第 4 层｜权重（买几只、各多少）**
Top 3 等权，单只上限 45%。

**第 5 层｜换手与风险控制**
排名缓冲带（现有持仓在 top6 内即保留）；原回撤熔断经消融验证为负贡献，默认关闭；每 5 交易日调仓。

### 5.2 选股条件（可直接执行）

1. 沪深 ETF，剔除货币，同指数只留成交额最大者
2. 上市 ≥ 250 交易日
3. 20 日均成交额 ≥ 2000 万元
4. 收盘价 > MA60
5. 量比(5/60) < 3.0
6. 按 R20(skip 5) 降序
7. 取前 3 名等权，单只 ≤ 45%
8. 总仓位由 regime 决定 100% / 50%
9. 剩余敞口配 R20 最强债券 ETF
10. 每 5 交易日调仓，T+1 开盘执行

## 七、验证实验（关键结论）

> 外部策略的评估标准（五道闸门、标准实验协议、红旗清单、已做完的对照）见 [`docs/strategy_dd.md`](docs/strategy_dd.md)。7.3、7.6~7.9 都是按它执行的。
> 外部策略的**目录**（72 条，按族分类、逐条标注对本项目的可迁移性）见 [`docs/github_strategies.md`](docs/github_strategies.md)——先查表，避免重复测同一类东西。

### 7.1 增量归因（从纯动量逐项叠加）

| 步骤 | CAGR | 夏普 | 最大回撤 | 换手/年 | 结论 |
|---|---|---|---|---|---|
| 纯动量(起点) | 20.48% | 0.69 | -38.28% | 26.3 | 核心 alpha 来自动量本身 |
| + 趋势过滤 MA60 | 13.66% | 0.52 | -42.25% | 26.3 | 单独加有害 |
| + 拥挤度过滤 | 15.60% | 0.58 | -47.85% | 27.2 | 与趋势过滤存在交互 |
| + 排名缓冲带 | 19.68% | 0.70 | -47.15% | 20.9 | 同时改善收益与夏普、并降低换手 |
| + 市场状态闸门 | 14.82% | 0.62 | -29.17% | 26.5 | 以收益换回撤 |
| + 回撤熔断 | 12.51% | 0.55 | -30.59% | 26.8 | **负贡献，已剔除** |
| 闸门改为仅降半仓(不空仓) | 17.28% | 0.69 | -28.86% | 24.2 | 优于允许空仓 |
| 多因子打分替代纯动量 | 14.30% | 0.61 | -27.03% | 24.0 | 核心 alpha 来自动量本身 |
| 波动率倒数加权 | 15.79% | 0.66 | -26.82% | 27.1 | 略劣于等权 |
| Top5 分散 | 10.27% | 0.48 | -27.77% | 23.8 | 分散过度 |

三条与直觉相反的结论：

1. **多因子合成劣于纯短期动量**（14.3% vs 17.3%）。A 股 ETF 行业轮动周期以 3-8 周为主，中期动量与低波动因子会系统性低配刚启动的高弹性品种。
2. **回撤熔断是负贡献**。在下跌末期减仓形成追跌，收益从 17.3% 降到 14.5%，回撤也未见改善。
3. **调仓周期极度敏感**。5 日 → 17.3%，10 日 → 13.8%，20 日 → 9.5%。策略依赖短周期轮动窗口。

### 7.2 子样本稳定性

| 区间 | 基准 CAGR | 纯动量 CAGR | TGAR CAGR | 基准 MaxDD | TGAR MaxDD |
|---|---|---|---|---|---|
| 前段 2019-2022 | 10.6% | 13.3% | 9.0% | -40.2% | -23.9% |
| 后段 2023-2026 | 4.0% | 29.2% | 26.7% | -24.2% | -27.9% |

**超额收益高度集中在 2023-2026 段**，2019-2022 段跑输基准但回撤显著更浅。
该策略的真实定位是"熊市抗跌 + 结构性行情中捕捉行业轮动"，而非全天候跑赢。

### 7.3 外部策略移植实验（负结果）

把 GitHub 上三条主流改进挂到 TGAR 上逐条验证，全部作为**默认关闭的可选开关**实现
（`dedup_corr` / `sleeve_n` / `vol_target`），复现脚本 `scripts/research/ab_test.py`。

| 思路 | 来源仓库 | 核心做法 |
|---|---|---|
| 同质化去重 | `guoyaohua/etf-adaptive-rotation-qmt`、`fadaiba/a-share-etf-rotation` | 候选间 N 日收益相关性 ≥ 阈值时只留分数最高的一只 |
| 错峰子组合 | `guoyaohua`（staggered_weeks） | 目标权重 = 最近 N 次信号等权平均，把一次大调仓摊成 N 次 |
| 波动率目标 | `AbacusFlow/quant` V1、`fadaiba` | 权益仓位按「目标波动 / 近期已实现波动」缩放，腾出的额度转债券 |

**结果（2019-01-02 ~ 2026-10-27，沪深300 为基准）**：

| 变体 | CAGR | MaxDD | Sharpe | 换手 | 2019-22 | 2023-26 |
|---|---|---|---|---|---|---|
| 基线（5 日调仓） | **17.27%** | −28.86% | **0.69** | 24.2 | 9.0% | **26.7%** |
| 去重 0.90 / 0.95 / 0.97 | 12.75 / 15.07 / 12.53% | −29.7 / −33.2 / −30.7% | 0.56 / 0.63 / 0.54 | ≈23 | — | — |
| 错峰 2 周 / 4 周 | 13.11 / 14.80% | −32.4 / −32.2% | 0.57 / 0.65 | 16.3 / 10.5 | 12% | 18% |
| 波动闸 25% / 30% | 12.07 / 13.44% | −24.8 / −27.1% | 0.60 / 0.62 | ≈25 | 9% | 18% |
| 错峰4 + 波动闸30% | 14.33% | **−22.96%** | **0.71** | 10.5 | 12% | 16% |

**结论：三条都不成立，不并入主线。**

1. **唯一在风险调整后超过基线的组合（Sharpe 0.71 vs 0.69），优势只存在于 2019-2022**；
   2023-2026 段年化 16% vs 基线 27%，落后 11 个百分点。全样本的好看数字是前段的贡献，
   属于典型的数据挖掘，不能作为上线依据。
2. **去重反而更差**：被去重打掉的那只"重复标的"恰恰是当期最强的主题，
   换成下一个候选等于用弱势品种替掉强势品种，波动没降、收益先掉。
3. **错峰把成本砍掉一半（累计成本 36.4% → 15.8%），但权益只数从 3 只稀释到 6.5 只**，
   信号还滞后 4 周——省下的 2.4%/年 成本，抵不上动量衰减的损失。
4. **波动闸只减不增**，目标值贴近策略自然波动（27%）时仍有 3-5 个百分点的收益损失，
   卡玛比率从 0.60 降到 0.50~0.57，风险调整后并没有变好。

**调仓频率敏感性**（反向验证"alpha 衰减快"）：2 日 16.27%、3 日 12.18%、5 日 **17.27%**、
10 日 14.00%、20 日 9.48%。5 日是局部最优，但 3 日掉到 12.18% 这种非单调现象说明
**单点参数的排名本身带噪声**，17.27% 这个数字也含参数选择运气——这一点在解读全表时同样适用。

**为什么移植不过来**：这些仓库的池子是 9~20 只手工挑选的大类资产（股/债/金/商品），
alpha 来自资产类别分散，平滑与波动控制天然有效；本项目是 260 只 ETF 的横截面主题动量，
alpha 来自"尽快换到最强主题"，任何平滑都在削弱这个来源。

### 7.4 池子范围与闸门判据（含一次自我纠错）

**（1）剔除大盘宽基：无效。**

假设是：沪深300/上证50/中证500 本质是同一个大盘 beta，闸门已经在管它，
放进打分池等于对同一份暴露收两次费。用 `etfquant.universe.apply_pool("core")`
（保留列、只打 `tradable=False`，基准仍可算趋势）实测：

| 口径 | CAGR | MaxDD | Sharpe |
|---|---|---|---|
| 全池 260 只 | **17.27%** | −28.86% | **0.69** |
| 剔除大盘宽基 23 只 | 16.74% | −29.47% | 0.67 |

**⚠️ 自我纠错**：最初这组实验显示剔除宽基能把 CAGR 提到 20.46%，但那是**把宽基列整列删掉**
做的——沪深300 也在被删之列，`_bench_series()` 随即退化为"宽基等权代理"、再退化为
"全池等权"，实际测的是**换闸门判据**而不是换池子。改用 `tradable` 标记后效应消失。
这类"改动 A 却意外改动了 B"的污染，只能靠把两个变量拆开重跑才能发现。

**（2）闸门判据：有改善，但不稳健。**

顺着上面的线索，把闸门输入从沪深300 换成"池内非债券标的等权净值"（`gate_mode="breadth"`）：

| 判据 | 调仓 | CAGR | MaxDD | Sharpe | 19-21 | 22-23 | 24-26 |
|---|---|---|---|---|---|---|---|
| 沪深300（现网） | 5 日 | 17.27% | −28.86% | 0.69 | 14.8% | −3.6% | 37.9% |
| breadth | 5 日 | **19.27%** | −28.21% | **0.76** | 20.4% | −2.0% | 35.8% |
| 沪深300（现网） | 10 日 | **14.00%** | −33.49% | **0.59** | 23.7% | −8.0% | 21.9% |
| breadth | 10 日 | 12.26% | −33.62% | 0.53 | 20.6% | −8.0% | 20.0% |

5 日调仓下三项指标全面改善，两个子区间也更好；但**10 日调仓下反向变差**。
为此又做了滚动窗口检验（`scripts/research/rolling_gate.py`，窗口内不调参）：

| 口径 | 窗口数 | breadth 收益更高 | 收益差中位数 | 最近 4 个窗口 |
|---|---|---|---|---|
| 5 日 · 12 个月窗 | 15 | 10 个（67%） | +1.2pp | −12.0 / −11.0pp（转负） |
| 5 日 · 24 个月窗 | 15 | 11 个（73%） | +1.6pp | −4.0 / −3.6 / −6.0 / −11.0pp（全负） |
| 10 日 · 24 个月窗 | 15 | **3 个（20%）** | **−1.7pp** | 全负 |

**结论：优势不连续。** 它集中在 2019-2023，最近 12~18 个月已是负贡献；换个调仓频率
甚至只剩 20% 的窗口获胜。这种"换个参数就翻向"的改进属于参数运气，**不设为默认**，
只保留 `gate_mode` 作为可复现的实验开关。

> 附：项目"已知缺陷"里原本就写着"闸门以沪深300 判断市场状态，与池内 62 只跨境 ETF
> 和 4 只商品 ETF 错配"。上面的 breadth 判据正是针对这一条，但目前证据还不足以定论。

### 7.5 过拟合体检（PBO / Deflated Sharpe / 滚动前向）

前面几节都是"某个改动好不好"，这一节问的是更根本的问题：**这套结果里有多少是挑出来的**。
方法：把项目实际探索过的 29 个变体（一个参数一动，外加几个双参数组合）各跑一遍，
用三把尺子量"挑选过程"本身。复现：`python scripts/overfit_check.py`。

**① 挑冠军是不是在挑噪声（CSCV / PBO）** — 16 块、12870 个组合：

| 指标 | 值 | 读法 |
|---|---|---|
| **PBO** | **43.2%** | 样本内冠军有 43.2% 的概率在样本外掉到中位数以下。0 理想，>50% 属严重 |
| 样本内 Sharpe 中位 | 0.898 | 挑选者看到的 |
| 样本外 Sharpe 中位 | 0.668 | 实际能拿到的 |
| 衰减 | −0.230（−26%） | 挑选带来的乐观偏差 |

**② 试了这么多次之后还剩多少显著性（Deflated Sharpe）**：

| 口径 | N | 多重检验临界 Sharpe | 实际 | DSR |
|---|---|---|---|---|
| 网格最优（`minamt1e7`） | 29 | 0.19 | 0.78 | 94.8% |
| 同上，计入历史全部试验 | 60 | 0.21 | 0.78 | 94.0% |
| **默认参数（未参与挑选）** | 29 | — | 0.70 | **91.9%** |

**③ 每 6 个月重挑一次参数，实盘会怎样（滚动前向，2 年样本内 / 6 个月样本外）**：

| 口径 | 年化 |
|---|---|
| 滚动重挑（11 个窗口拼接，纯样本外） | **12.62%** |
| 同区间固定默认参数 | **15.41%** |

选中的变体在窗口间乱跳（rmid0.6 → freq10×4 → top2 → score_multi×3 → buffer1 → vr2），
没有一个参数能连续四次被选中。**"选参数"这件事本身没有持续性，且比不选差 2.8pp/年。**

**④ 默认值踩在平台上还是尖峰上**（各参数单独变动时的 Sharpe）：

| 参数 | 取值 → Sharpe | 极差 | 判断 |
|---|---|---|---|
| `rebalance_freq` | 3:0.538 · **5:0.696** · 10:0.597 · 20:0.430 | 0.185 | **尖峰**，高危 |
| `min_hist` | 120:0.655 · **250:0.696** · 500:0.442 | 0.213 | **尖峰**，高危 |
| `min_amount` | 1e7:0.781 · **2e7:0.696** · 5e7:0.652 | 0.128 | 单调，放宽更好但有容量风险 |
| `top_n` | 2:0.600 · **3:0.696** · 4:0.616 · 5:0.574 | 0.042 | 平台，安全 |
| `max_weight` | 0.35 / 0.60 / 1.00 **全部 0.696** | 0.000 | **死参数**（Top3 等权 33% 从不触顶），保留作集中度保险 |
| ~~`regime_low`~~ | 0.2 / 0.35 / 0.5 **全部 0.696** | 0.000 | **已移除**（2026-10-29）：第三档与第二档敞口相同，改为默认关闭的可选档 |
| `buffer_mult` | 1:0.598 · **2:0.696** · 3:0.674 | 0.076 | 平台偏尖 |

**⑤ 参数集成能否抵消单点运气**（两 sleeve 等权，按日收益合成）：

| 组合 | 年化 | 夏普 | 回撤 | 2019-22 | 2023-26 |
|---|---|---|---|---|---|
| 单用 5 日（现状） | **17.45%** | 0.696 | −28.86% | 9.3% | **28.3%** |
| 5 日 + 10 日 | 16.06% | 0.669 | −28.74% | 12.0% | 21.9% |
| 3/5/10 日三频 | 15.02% | 0.644 | −28.75% | 11.6% | 20.1% |
| 5 日 + 逆波动加权 | 18.05% | 0.719 | −28.32% | 9.2% | 29.8% |

集成本该降低方差，但这里**换了频率反而更低**（16.06% vs 17.45%）：alpha 来自"尽快换到最强主题"，
把频率掺半等于稀释它。后两行数字更好看，但它们同样是"在本样本上比出来的"——正是 ① 警告的那件事。

#### 结论

**有过拟合，但主要集中在"参数选择过程"，不在"策略结构"。**

- **结构是稳的**：29 个变体**全部**跑赢基准（最差的 `freq20` 夏普 0.430 > 基准 0.38）。
  把参数从 5 日改成 20 日、把权重改成逆波动，都还是同一类赚钱逻辑。
- **参数选择是虚的**：PBO 43.2%、滚动重挑比固定默认差 2.8pp/年、选中变体在窗口间乱跳。
- **默认值没有精确挑到最优点**：它在网格里并列第 5（与三个 `max_weight` 取值结果相同），
  前面 4 个更好的都没上线。
  这反而降低了"参数过拟合"的嫌疑——如果当初真按样本内最优上线，上的会是 `minamt1e7`。
- **自由度是虚高的**：`max_weight` 与 `regime_low` 完全不改变结果（极差 0.000）。
  `regime_low` 已于 2026-10-29 降级为"默认关闭的可选第三档"，闸门只剩两档
  （`>= 0.7` 满敞口，否则半敞口），界面标签也同步从三态改为"进攻 / 防守"两态。

#### 优化（按"确定性 / 代价"排序）

1. ✅ **删掉死参数**（2026-10-29 已执行，零业绩影响）：`regime_low` 改为 `None`（关闭第三档），
   `expo_low` 随之默认等于 `expo_mid`；界面标签由三态降为两态。改后回测净值与改前
   **逐位相同**（CAGR 17.4473% / Sharpe 0.695826 / MDD −28.8638%）。
   `max_weight` 保留但标注"Top3 等权下永不触顶"，`top_n` 固定 3。
2. ✅ **报告数字打折**（2026-10-29 已执行）：样本内 17.45% 只作上限，对外口径 **11%~13%**
   （锚点 12.62%），并同时给出 PBO 与折扣。换算规则收在 `etfquant/expectation.py`，
   README 6.2、桌面总览与实验四、手机验证页、月报全部读同一份，禁止各处手写数字。
3. **停止在 2019-2026 上调参**。本轮已经看到：表现更好的三个变体（`minamt1e7` +2.7pp、
   `weight_invvol` +1.2pp、`rmid0.8` +0.8pp）都在同一个陷阱里；按 ② 的 DSR 它们并不显著优于默认。
4. **尖峰参数改用邻域平均而非最优点**：`rebalance_freq` 与 `min_hist` 是尖峰，
   若将来必须动，取"相邻两档的平均表现最好的中心"，而不是单点最优。
5. **唯一还有价值的验证是前向**：`data/signal_archive.csv` + 「实盘跟踪」已经能记录每期真实信号，
   跑满 3~6 个月后再看纸上净值与回测的偏差——这是唯一不依赖"同一段历史"的证据。

> **不做的事**：`min_amount` 放宽到 1e7 能让 CAGR 到 20.19%，但那会把日均成交 1000~2000 万的
> 标的放进池子，容量与冲击成本都会恶化；这属于"回测更优、实盘更差"的典型，不采纳。

原因是两个因子并不独立：排名相关中位 **0.56**、Top3 重合度 **67%**——掺一半普通动量进来，
等于把残差已经排好的结果往弱因子的方向拉回一点。原文"双因子 61.79% > 单动量 58.51% >
单残差 33.57%"这个量级的差别，在我们的数据上完全看不到。

**④ 真正的瓶颈还是"12 个月 + 月度"**

同一个池子、同样 Top3，只把因子换成 20 日、调仓换成 5 日：8.1% → **13.1%**，
回撤 −50.1% → **−44.0%**（2023 起更明显：8.7% → 13.8%）。alpha 来自"追最强"，
而 12 个月窗口太长、月末调仓太慢——等它确认"主线"，主线已经走完一半。

**⑤ 异常月补丁是拟合**

"把日波动最高月份的残差从加分改为扣分"：同起点 6.3% vs 无补丁 9.4%（**−3.1pp**），
2023 起 5.3% vs 6.4%（−1.1pp），只有原文那个短窗口是 +0.7pp。三个窗口两个为负、
幅度还不稳定，说明它服务的是某段历史里的单次暴涨，没有机制解释，不采纳。

**⑥ 真正值得借鉴的两点**

1. **残差因子本身**：这套里表现最好的单因子就是它（9.4%，回撤 −39.5%），比普通 12 月动量
   好 2.3pp 且回撤浅 5.5pp。它衡量的是"扣掉大盘顺风后行业自己的涨幅"，和本项目的闸门
   （判断大盘状态）是互补而非重复的，值得在短周期框架里单独试。
2. **换手只有 3.2 倍/年**，是 TGAR（25.1 倍）的 1/8，单边 0.10% 下成本差约 **4pp/年**——
   这正好是 7.5 节指出的最大漏损。但"降换手"这条路我们走过：10 日 → 13.8%、换手 16 倍；
   再降到月度，回撤从 −28.9% 掉到 −50%。**同一条风险-收益曲线，它站在更靠右（更危险）的位置。**

**⑦ 后续：把残差因子接到 5 日框架（负结果）**

上面第 ⑥ 条留下的唯一悬念是"残差因子本身"。那就放进我们自己的框架里再问一次：
不月度、不 12 个月，改 5 日调仓 + 日频回归（252 日）/ 残差求和 120 日。
复现：`python scripts/research/ab_resid.py`（`etfquant/resid_mom.py`，6 项单测）。

| 用法（同起点 2020-01，6.8 年） | CAGR | 夏普 | 最大回撤 | 卡玛 | 2020-22 | 2023-26 |
|---|---|---|---|---|---|---|
| 基线 R20（现状） | 19.6% | 0.75 | -28.9% | 0.68 | 10.8% | 27.0% |
| +残差 20%（混合） | 22.2% | 0.81 | -29.3% | 0.76 | 16.6% | 26.7% |
| +残差 30%（混合） | 18.4% | 0.70 | -30.6% | 0.60 | 13.2% | 22.6% |
| +残差 50%（混合） | 18.4% | 0.70 | -34.4% | 0.53 | 12.5% | 23.1% |
| 仅残差（替代 R20） | 13.1% | 0.55 | -36.3% | 0.36 | 17.0% | 9.7% |
| R20 + 残差>0 过滤 | 18.4% | 0.72 | -36.5% | 0.51 | 6.2% | 29.0% |

**判据是事先写死的**：主窗口改善不算数，必须 2020-22 与 2023-26 **两段同向改善**；
通过后才看权重（0.2 / 0.3）× 残差窗口（60 / 120 / 250）的邻域是否稳定。

结果 **0/6 通过**：

- `w=0.2 / window=250` 看上去最好（22.7%，回撤 −25.8%），但 2023-26 是 **26.0% < 基线 27.0%**；
- `w=0.3 / window=250` 把 2023-26 拉到 **32.6%**、回撤 −23.8%，但 2020-22 只剩 **6.6%**（基线 10.8%）；
- `w=0.3 / window=60` 直接掉到 13.0%（2020-22 仅 1.5%）。

每一条都恰好在一段赢、另一段输，而且**权重与窗口的响应不单调**（0.2 好、0.3 差、0.5 又回正）——
这是数据挖掘曲面的形状，不是因子效应。

失败原因有三个机制层面的解释（不是事后找补）：① R20 是"此刻最强主题"的快照，
120 日残差和是"过去四个月比自己的 beta 多涨了多少"，天然滞后，等它转正时主题往往已经换了；
② 混合打分用一半权重把"尽快换到最强"拉回"稳健"方向，与 7.1 的"多因子合成劣于纯动量"是同一规律；
③ 单独用残差时 2023-26 只剩 9.7%（2020-22 有 17.0%），这个因子近两年在 A 股 ETF 上明显衰减。

**结论**：不并入主线。它有参考价值的地方不在"照抄"，而在于低换手的成本提醒；
残差因子的两次尝试（月度 12 个月 / 5 日 120 日）都没有通过跨期一致性检验，
`score_mode` 的 `resid` / `r20+resid` / `r20+resid_filter` 只作为**默认关闭**的实验开关保留
（与 `dedup_corr` / `vol_target` 同类）。它自己也承认"无法单独穿越牛熊，需叠加市场状态判断"
——那个判断就是本项目的闸门；装上闸门后它并没有更强：同起点 TGAR **19.6% / −28.9% / 卡玛 0.68**，
对双因子 **8.1% / −50.1% / 0.16**。

### 7.7 外部策略对照：均线金叉死叉波段（5/20 + MA60 过滤）

视频流传的一套"ETF 均线波段"：选 MA60 走平或向上的 ETF，5 日线上穿 20 日线（金叉）买入、
下穿（死叉）离场，下跌可小止损或等下一次金叉补仓摊薄。
复现：`python scripts/research/ab_macross.py`（`etfquant/macross.py`，7 项单测）。

原文没说清的两处做了显式选择：多只同时出信号 → 池内满足条件者**等权**（"分批进场"的组合化）；
空仓期 → 现金。**"补仓摊薄"无法在组合级回测忠实复现（需要单持仓加仓记账），如实标注为未测**——
它的逻辑（跌了加仓）与死叉离场的风控互相矛盾，2022-2024 那种连续阴跌里等于越摊越重。

| 策略（2019-01 ~ 2026-10，双边 0.10%） | CAGR | 夏普 | 最大回撤 | 卡玛 | 年换手 | 2020-22 | 2023-26 |
|---|---|---|---|---|---|---|---|
| 均线波段 + MA60 过滤（原文） | 12.8% | 0.82 | -24.6% | 0.52 | 31.5 | 6.4% | -12.5% |
| 均线波段（无 MA60 过滤） | 12.6% | 0.79 | -20.5% | 0.61 | 29.7 | 7.0% | -15.9% |
| 单只沪深300ETF 波段 | -2.3% | -0.23 | -40.0% | -0.06 | 6.9 | -4.7% | -22.3% |
| 本项目 TGAR（对照） | 17.4% | 0.70 | -28.9% | 0.60 | 24.2 | 27.0% | -23.9% |
| 沪深300 买入持有 | 7.2% | 0.38 | -44.7% | 0.16 | 0.0 | — | — |

**① 最常用的用法最伤：单只宽基波段是亏钱的**

视频面向的场景就是"盯着一两只 ETF 做波段"。在沪深300ETF 上按 5/20 金叉死叉全仓进出，
2019-2026 年化 **-2.3%**（回撤 −40.0%），而拿着不动是 **+7.2%**（回撤 −44.7%）。
8 年里只有 35% 的时间在场：每次金叉进场时行情已走一段，死叉离场时常在回调尾部，
宽基指数长期无趋势、震荡占比高，均线策略在噪声里反复交学费。**对单只宽基，这条规则是负期望。**

**② 全池扫描版能活，但不是更好**

260 只各自独立执行金叉死叉、满足条件者等权：年化 12.8%，比 TGAR 低 4.6pp，
但夏普更高（0.82 vs 0.70）、回撤浅 4.3pp——代价是年换手 31.5 倍（比主线还高）。
值得注意的不是"哪个好"，而是**两段子区间完全反号**：

- 2020-22（阴跌熊）：**20.2% vs TGAR 10.8%**。快进快出在持续下跌里防守确实好——
  死叉离场天然是个"下跌止损"，避免了 TGAR 那种"半仓硬扛"的路径；
- 2023-26（主题轮动牛）：**6.4% vs TGAR 27.0%**。轮动行情里金叉追进的是"已经涨完一段"的，
  死叉离场又刚好卖在回调尾部，反复被扫。

这和 7.1/7.6 是同一条规律：**没有全天候的快，只有特定环境下的快**。均线波段是一张
"熊市看跌期权"，牛市里它的保费是踏空 20pp。

**③ 视频里的"MA60 安全垫"没有起作用**

去掉 MA60 过滤：12.6% vs 12.8%，回撤反而更浅（−20.5% vs −24.6%）。过滤器的本意是
"只做趋势向上的"，但它删掉的恰恰是 2020-22 段里那些"深度超跌后金叉"的最好反弹机会。

**结论**：不并入主线。单只宽基波段是负期望（比买入持有差 9.5pp/年）；
全池扫描版是 TGAR 的互补形状而非改进——若将来真想利用它的防守特性，
正确的问题不是"替换 TGAR"，而是"阴跌熊市里 TGAR 的半仓是否足够"，
那是闸门参数（regime 阈值）的领地，且 7.5 已裁定停止在这段历史上调参。

### 7.8 外部策略对照：动量 + 波动率双因子月度 Top3（视频版）

又一套流传较广的规则：池内按「动量 + 波动率」打分，每月买前 3，跌出即卖。
声称 2024-2025 年化 **40%、回撤 6.5%、胜率 80%**；视频自己承认拉长到 2015-2025 会大幅缩水。
复现：`python scripts/research/ab_momvol.py`——参数取最朴素的一组（3 个月动量 + 3 个月低波、
50/50 与 70/30 两档排名合成、上市满 12 个月才参与），**没有做任何挑选**：
本实验要验证的是"漂亮窗口 vs 长窗口"的落差，在这里挑参数，实验就变成了它批评的对象。

| 窗口 | 动量+低波 50/50 | 70/30 | TGAR（对照） | 沪深300 |
|---|---|---|---|---|
| 视频窗口 2024-01~2025-12 | -23.3% / -49.1% | -12.6% / -41.7% | 25.9% / -26.5% | 21.7% / -17.1% |
| 全样本 2019-01~2026-10 | -8.0% / -76.8% | -7.4% / -76.2% | 17.3% / -28.9% | 7.4% / -44.7% |
| 2020-22 | 6.6% / -33.5% | 4.2% / -39.2% | 10.8% / -23.9% | -0.6% / -40.2% |
| 2023-26 | -25.5% / -75.9% | -23.6% / -70.6% | 26.8% / -27.9% | 3.6% / -24.2% |

（29% 是我们池内版的视频窗口月胜率；同期基准月胜率 62%。）

**三条看法**

1. **40% / 6.5% / 80% 这组数字内部就不自洽**。2024-01~2025-12 里沪深300 自身的最大回撤
   是 **−17.1%**（1 月微盘股崩塌 + 9·24 暴力反转）。一个每月满仓 3 只 ETF 的组合，
   在基准都跌 17% 的窗口里把回撤压到 6.5%，只有两种可能：大部分时间空仓（那 40% 年化
   无从谈起），或池子/入场时点是事后挑的。附带一个可以随身携带的红旗判据：
   **月度调仓策略 Calmar > 3，先怀疑数据，再怀疑运气，最后才考虑是真本事**
   （本策略 Calmar ≈ 6；本项目打磨了 8 年的 TGAR 是 0.6~0.7；顶级 CTA 长期能到 1~2）。
2. **在无偏的池子上，这条规则不是"缩水"，是负的**。我们的 260 只池、point-in-time、
   次新剔除，四个窗口全负（视频窗口 −23.3%，全样本 −8.0%，回撤 −77%），月胜率 29%。
   视频里的 40% 大概率来自三件事的叠加：手工挑的十几只知名 ETF（2024-25 恰好是
   科技/纳指的两年）+ 两年的短窗口 + 未说明的细节（止损/择时）。视频自己拉长到
   2015-2025 后"收益缩水明显"，与我们两次独立复现（7.6 双因子、本节）的结论一致。
3. **视频的药方只对了一半**。"用更长历史验证"仍然是在**同一段历史上**验证——
   如果策略是因为长历史表现好才被选出来，多重检验问题原封不动。ETF 类策略还有一个
   额外天花板：2019 年初全市场可选的主题 ETF 只有 40 只（见已知局限第 10 条），
   "2015-2025 的 ETF 回测"本身就被幸存者偏差严重污染。真正站得住的证据只有两种：
   事先注册的判据 + 纯样本外拼接（本项目 7.5 的滚动前向），以及**前向跟踪**
   （「实盘跟踪」+ 月报，正在积累）。

**结论**：这条视频的价值不在策略本身（规则未说明处太多，无偏复现即失效），
而在它得出的教训与本项目 7.5/已知局限第 9 条完全一致。它没说完整的后半句是：
**长历史回测也只能证明"在长历史上有效"，永远无法替代前向验证。**

### 7.9 外部策略对照：缠论「按笔交易」（含一次未来函数自查）

缠中说禅体系的信号层是「分型 → 笔 → 线段 → 中枢 → 背驰 → 三类买卖点」。
完整实现不可行：线段/中枢/背驰的判定有多个流派约定（包含处理、中枢升级、背驰用面积还是峰值），
不同实现给出不同信号，测出来的不是缠论而是某一版实现。所以只测它的地基——**按笔交易**：
向上笔持有、向下笔空仓（笔规则见 `etfquant/chan.py`，4 项单测，其中 3 项是因果性）。
复现：`python scripts/research/ab_chan.py`。

| 版本（2019-01 ~ 2026-10） | CAGR | 最大回撤 | 夏普 | 年换手 | 2020-22 | 2023-26 |
|---|---|---|---|---|---|---|
| 缠论在线 · 单只沪深300ETF | 4.7% | -34.0% | 0.30 | 9.9 | 3.5% | 4.1% |
| 缠论在线 · 全池扫描 | 7.7% | -35.7% | 0.46 | 36.0 | 8.7% | 0.8% |
| 【未来函数】离线端点·单只 | 37.3% | -9.3% | 2.20 | 10.0 | 39.7% | 24.9% |
| 【未来函数】离线端点·全池 | 63.8% | -9.9% | 3.50 | 35.4 | 75.6% | 53.2% |
| 本项目 TGAR（对照） | 17.3% | -28.9% | 0.69 | 24.2 | 10.8% | 26.8% |
| 沪深300 买入持有 | 7.4% | -44.7% | 0.37 | 0.0 | -0.6% | 3.6% |

**① 一个必须交代的自查：第一版回测出了 63.8%，是未来函数**

第一版用"全样本笔端点 + 2 个交易日确认滞后"回放状态，跑出单只 37.3%、全池 **63.8%**（夏普 3.50）。
按本项目自己的判据（Calmar > 3 先怀疑数据）复查后发现：**当前笔的端点本身是临时的**——
上涨途中会出现一个个"临时顶"，事后被更高的顶替换；用全样本端点回放，等于提前知道顶在哪，
把每一次本该发生的"假死叉"抹掉了。改成逐日在线状态机（`chan.online_states`）后：

- 单只沪深300ETF：CAGR **4.7%**（买入持有 7.4%），回撤 −34.0%，**跑输拿着不动**；
- 全池扫描：CAGR **7.7%**，回撤 −35.7%，同期 TGAR 17.3% / −28.9%；
- 两个版本之间差 **8~10 倍**——这就是"事后画线再回测"这种做法的全部收益来源。

**② 为什么在线版会差这么多**

笔的确认天生滞后：一根合并K线的分型要等下一根出现，反向分型还要满足间隔条件。
在上涨过程中，"临时顶"会反复触发离场，然后价格继续涨——**假死叉的成本全由实盘承担**。
离线版把这些假死叉全部抹掉了，所以看起来"精准抄底逃顶"。

**③ 对策略本身的价值判断**

按笔交易在我们的数据上不成立，原因与 7.7 的均线波段同源：**它是一套反转/波段择时规则，
而 A 股 ETF 的收益主要来自趋势延续**。缠论真正有价值的部分是"级别"与"中枢"的世界观
（把行情拆成震荡与离开震荡），但那是**描述框架**，不是可执行的 alpha；
把它机械化到可回测的程度，就退化成"分型突破"，而分型突破已经被 7.7 证否。

**结论**：不并入主线。这条实验最大的产出不是"缠论不行"，而是
**量化了"事后画线"能虚增多少**：8~10 倍 CAGR、回撤砍掉 2/3。
任何用截图讲缠论的教程都绕不开这一点。

| ④ 执行延迟 | 中位 **0.0bp** —— 我原先"动量买单要高开、每年漏 4pp"的假设是错的 |
| ⑤ 容量 | 瓶颈不在选股（都很流动），在**防御债券腿**：ADV 仅几十万 |
| ⑥ 误差棒 | CAGR 95% CI **[−1.9%, 40.9%]**；历史回撤 −28.9% 是同分布下的**幸运路径** |
| ⑦ 集中度 | "选强"稳健（任何 N 都跑赢基准 11pp 以上），"恰好吃 3 只"**不可识别** |
| ⑧ 分区间 | **没有衰减**（趋势 t=0.43），但尾部效应**只存在于 2023-2026**（2019-22 为 −2.7bp） |

**① 信号：IC 说没有，尾部说有的，两个都说"还不够"**

| 持有期 | 1d | 5d | 10d | 20d | 60d |
|---|---|---|---|---|---|
| rank IC | 0.029 | 0.020 | 0.018 | −0.004 | −0.024 |
| Newey-West t | 1.65 | 1.19 | 0.82 | −0.15 | −0.86 |
| Q9−Q0 价差 | +0.5bp | **+27.1bp** | +31.1bp | +27.7bp | −95.3bp |

秩相关只有 0.02，看起来像没信号——但这是**IC 这个指标的问题，不是信号的问题**：
R20 的收益集中在头尾两端，中间几组几乎是平的，整条横截面做秩相关等于用中间的噪声
稀释掉两端的信号。直接看策略真正做的事（买前 3）：

| | 均值 | 中位 | 胜率 | t(NW) |
|---|---|---|---|---|
| top3 − 全池（5 日） | **+29.3bp** | +8.3bp | 52% | **1.57** |
| top3 − 全池（20 日） | +61.3bp | −17.1bp | 49% | 1.09 |

均值远大于中位、胜率只有 52%：**动量策略的典型形状——多数小亏，少数大赢**。
而 t=1.57 意味着，在 7.8 年、375 个决策日上，"选的 3 只比池子平均好"这件事
**仍然没有达到 5% 显著**。这是本次诊断最重要的一句话。

**② 归因：把 17.3% 拆开**

用**自己的池子**造多空动量因子（每月末 R20 前/后 10% 等权多空，次日生效），
再加小盘代理（中证1000 − 沪深300）和大盘，做 HAC 回归：

| 来源 | 因子年化 | β | 贡献 |
|---|---|---|---|
| 大盘 | 8.7% | 0.71（t=21） | 6.1pp |
| 动量（本池多空） | 10.9% | 0.37（t=14） | 4.1pp |
| 小盘 | 3.1% | 0.32（t=9） | 1.0pp |
| **alpha** | — | — | **9.6pp（t=1.38）** |
| 波动拖累（−½σ²，σ=27%） | — | — | −3.5pp |
| 合计 | | | **17.3%** |

R² 0.53（只放大盘时 0.32），说明**这套策略一半的方差就是"大盘 + 动量 + 小盘"的某种配比**。
9.6pp 的 alpha 看似不小，但标准误约 7pp——它与 0 无法区分。

**③ 闸门：唯一经得起机制检验的部件**

闸门不是"空仓"，是把权益从 100% 降到 50%、另一半换债券（所以毛敞口恒为 1.0，
只看行和会误判成"闸门从不生效"）。实际 48% 的交易日满仓、52% 半仓。
把动量因子按敞口切开：

| | 年化 | 天数 |
|---|---|---|
| 闸门开（满仓） | **+24.9%** | 908 |
| 闸门关（半仓） | **−1.3%** | 988 |

关闸期间动量因子本身不赚钱——**这正是闸门该做的事**，而且不是拟合出来的故事：
它与 Daniel-Moskowitz 的"动量崩溃"（市场反转时动量组合暴跌）是同一个机制。
八个部件里，只有这一个既有先验逻辑、又有事后证据。（7.11 补了时间意义上的样本外检验：2015 股灾段把回撤从 −53.6% 压到 −33.6%。）

**④ 执行：我错了**

我此前的判断是"动量买单必然追高开，T+1 每年吃掉约 4pp"。实测 1260 笔真实成交：

- 买单平均 gap **−15.8bp**（次日开盘比信号日收盘**更便宜**），卖单 −3.4bp；
- 但**中位数是 0.0bp** —— 典型成交既没赚也没亏，均值完全由少数极端隔夜跳空支配；
- 加权后相当于每年 **−2.05%**（即比"收盘成交"多赚 2pp），但这个数字不可依赖。

结论：**执行延迟在本策略上既不是主要漏损，也不是稳定收益**，别指望改执行能捡钱。
顺带查出一个数据陷阱：9% 的成交落在成交额 <2000 万的薄量日，那天的 open 可能只是
几十手的零星成交（实测 `sz159906` 某日仅成交 3 手，open 0.76 / 收盘 0.85）。

**⑤ 容量：瓶颈在债券腿**

| AUM | 中位建仓天数 | p90 | 超 3 天的比例 |
|---|---|---|---|
| 1000 万 | 0.1 | 1.0 | 7% |
| 5000 万 | 0.6 | 5.1 | 17% |
| 1 亿 | 1.2 | 10.2 | 30% |
| 5 亿 | 6.1 | 51.0 | 64% |

"超 3 天"的 87 笔**全部是债券 ETF**（城投债 511220、地方债 511060，ADV20 仅几十万，
却要吃掉一半仓位）。权益选股本身很流动。所以：**这个策略的现实容量是千万级**，
放大到亿级时先换掉防御腿里那几只薄量债券 ETF。

**⑥ 误差棒：−28.9% 不是"这套策略的回撤"**

循环块 bootstrap（block=20，2000 次）：

| | 实际 | 95% CI | 中位 |
|---|---|---|---|
| CAGR | 17.3% | [−1.9%, 40.9%] | 16.8% |
| 最大回撤 | −28.9% | [−62.8%, −24.5%] | **−39.3%** |
| 夏普 | 0.69 | [0.06, 1.41] | — |

P(CAGR ≤ 0) = 4.4%。两条必须记住：
**① 历史最大回撤 −28.9% 落在分布的最好 2.5% 附近**——同分布的中位路径是 −39%，
5% 分位 −63%，"这套策略回撤 29%"是幸存路径的错觉；
**② 11%~13% 那个对外口径是"折价后的点估计"，不是置信区间**，
真正的区间宽度是 ±20pp——把它当作"预期会落在 11~13% 之间"是误读。

**⑦ 集中度：机制稳健，参数不可识别**

只改 `top_n`，其余全部不动，统一起点 2022-01（该时点池内 127 只，各档都能建仓）：

| | top1 | **top3** | top5 | top10 | top20 | top50 | 沪深300 |
|---|---|---|---|---|---|---|---|
| CAGR | 7.3% | **19.1%** | 13.2% | 10.1% | 10.9% | 9.2% | −2.2% |
| 回撤 | −30.4% | −27.9% | −25.4% | −25.9% | −24.9% | −20.7% | −34.9% |
| 夏普 | 0.39 | **0.73** | 0.56 | 0.48 | 0.54 | 0.51 | −0.10 |

能确认的：**"选最强"这件事有效**——任何集中度都跑赢基准 11pp 以上。
不能确认的：**"恰好 3 只"最优**——top3 是这条曲线上的单点尖峰，邻域低 6~9pp，
而 4.8 年样本的夏普标准误约 0.5，0.73 与 0.56 的差距在噪声内。
7.5 的 PBO 43% 在这里得到了独立印证。

**⑧ 分区间：没有衰减，但效应只活了半程**

全样本平均会掩盖两件相反的事，所以把同一把尺子放到子区间上（判据写在
`diagnostics.trend_test` 的 docstring 里，**跑之前定**：斜率 t<−2 判衰减、|t|<1 判无证据）：

| 区间（5 日） | 决策日 | IC | IC t | Q9−Q0 | top3−全池 | t | 胜率 |
|---|---|---|---|---|---|---|---|
| 2019-2022 | 191 | 0.023 | 1.04 | +21.7bp | **−2.7bp** | −0.12 | 50% |
| 2023-2026 | 185 | 0.017 | 0.67 | +31.7bp | **+62.5bp** | **2.14** | 54% |

年度 IC 逐年翻符号（2019 −0.002、2020 +0.045、2021 +0.033、2022 +0.013、
2023 +0.000、**2024 −0.033**、2025 +0.050、2026 +0.061）——**线性 IC 从来就不稳定，
只有尾部在承载信息**。这也解释了为什么 7.6 的双因子合成、7.3 的多因子加权全部失败：
它们优化的都是那条不稳定的整条横截面。

两条结论方向相反，必须同时说：

- **没有衰减证据。** IC 趋势 +33.5bp/年（t=0.43）、Q9−Q0 +5.1bp/年（t=0.47）、
  top3−全池 +17.2bp/年（t=1.99，方向还是**向上**）。所以"信号在变差"这个假设不成立——
  我之前怀疑"残差因子衰减了，R20 可能也是"是错的。
- **但"选强有效"的全部证据来自 2023-2026 这 185 个决策日。** 2019-2022 的
  top3−全池是 **−2.7bp（t=−0.12，等于零）**，2023-2026 才 +62.5bp（t=2.14）。
  换句话说：不是"效应很小"，而是**一半样本里根本没有效应**。

t=2.14 该不该信？我在同一次运行里做了 2 个区间 × 3 个指标 + 3 个趋势 = 9 次比较，
Bonferroni 阈值约 2.6——**它不过线**。按项目自己的纪律，这只能算"方向性证据"，
不能算"通过"。但它的方向与 7.5 的"超额几乎全部来自 2023-26"完全一致，
且全样本 t=1.57 现在有了机制解释：**这是一个 regime bet，不是全天候 alpha。**

**这八条改变了什么**

1. **对外表述必须改。** 不能说"年化 17.3%"，应该说"三种 beta 贡献 11.2pp、
   alpha 9.6pp（t=1.38，尚不显著）"。11%~13% 仍然是对外口径，但要同时说明它是折价点估计。
2. **停止改进信号，但理由要改。** 不是"信号在衰减"（⑧ 已证否），而是
   **它的有效区间只有一半、且集中在最近三年**——在这种样本结构上调参，
   调出来的必然是"2023-26 的形状"。7.1/7.3/7.6~7.9 的九次失败已经是实证。
3. **闸门是核心资产，不要再动。** 它是唯一有独立机制证据的部件（关闸期动量 −1.3%）。
4. **把精力放到活着能看到的地方**：前向跟踪（月报）、容量纪律（换债券腿）、
   以及承认"beta 占 2/3"之后的合理预期管理。

**已知局限（这次没做完的）**：月报的残差同时包含**选股**与**闸门择时**，没有拆分。
试着拆过（`(e−ē)·(r_eq−r_b)` 作择时项），恒等式不成立——因为策略约 26% 的仓位在债券里，
而回归的 β 已经把这层平均拖累吸收了，一旦把债券腿显式剥出来，就会多出 −12%/年 的
"债券 carry 差"项，看上去像个巨大的负 alpha。正确的做法是条件 β 模型
（β_t = β·e_t），或者直接对"权益腿收益"单独建模型——那是下一件事，不是这一件。

### 7.11 压力测试：闸门在 2015 股灾里管不管用

7.10 说"闸门是唯一有机制证据的部件"，但那个证据来自 2019-2026——**样本里没有真正的崩盘**。
这一节补的就是那段：把 36 只 2018 年前上市的 ETF 的缓存补到 2013 年，在
2014-02-10 ~ 2019-12 上重跑，重点看 2015-06-12（5178 点）→ 2016-01-28（熔断底）。

复现：`python -m etfquant research ab_early_era`（数据在 `data/cache_early`，
不生产化——原因见下）。

| 策略（2014-02 ~ 2019-12，5.89 年） | 累计 | 最大回撤 | CAGR | 卡玛 | **股灾段** | 年换手 |
|---|---|---|---|---|---|---|
| **TGAR（有闸门）** | +78.5% | **−37.0%** | 10.3% | 0.28 | **−33.6%** | 11.2 |
| 无闸门（永远满仓） | +18.2% | −57.8% | 2.9% | 0.05 | −53.6% | 9.2 |
| 沪深300 | +145.2% | −53.0% | 16.5% | 0.31 | −52.9% | 0 |

**① 闸门扛住了：股灾段少亏 20 个百分点**

−33.6% 对无闸门的 −53.6%、对沪深300 的 −52.9%。这是**时间意义上的样本外**——
2019-2026 的样本里根本没有这种行情，闸门的行为不是在这段历史里调出来的。
它把最大回撤砍掉 20.8pp（−57.8% → −37.0%），代价是全程 CAGR 从 2.9% 提到 10.3%
（因为它同时避开了 2016 年初的二次熔断）。

**② 但它是"减半"，不是"离场"，而且反应晚了两周**

| 月末 | regime | 敞口 | 本策略 | 沪深300 |
|---|---|---|---|---|
| 2015-04-30 | 1.00 | 100% | +124.0% | +170.4% |
| 2015-05-29 | 1.00 | 100% | +136.9% | +175.8% |
| **2015-06-30** | **0.40** | **50%** | +120.6% | +153.1% |
| 2015-08-31 | 0.00 | 50% | +90.2% | +79.0% |
| 2016-01-29 | 0.00 | 50% | +77.4% | +50.8% |

闸门到 **6 月 30 日**才降半仓，此时沪深300 已从峰值回撤 12.9%；它永远不可能抓到顶——
它读的是趋势，不是估值。真正的贡献在 8 月之后：regime 长期贴在 0，敞口一直 50%，
所以第二轮（8 月）和第三轮（2016 年 1 月熔断）只吃到一半跌幅。

**③ 反面证据：没有主题可选时，这套策略毫无优势**

- 2016-02 之后到 2019 年底，TGAR 累计 **+0.5%**（近四年白干）；
- 全程 CAGR 10.3% **低于**沪深300 的 16.5%，卡玛 0.28 也略低于 0.31。

原因不神秘：这 36 只里绝大多数是宽基和债券，**没有行业/主题 ETF 可轮**。
"从一堆主题里挑最强的三个"在 2014-2019 无米下锅。这从反面印证了 7.10 的结论：
alpha 依赖的是**主题池的宽度**，闸门只负责在崩盘时少亏。

**④ 三条必须写明的限制**

1. **幸存者偏差更重**：这 36 只是"活到今天"的，2015 年真实可选集合比它大，清盘的不在；
2. **横截面只有 20~30 只**，与主回测的 260 只不是一个量级，绝对值不可与 17.3% 比较；
3. **只回答"闸门有没有用"**，不产生任何年化预期——这段的年化数字不该被引用。

**⑤ 为什么数据要单独放一个目录**

把 2013-2017 并进生产缓存（`data/cache/kline_qfq`）会改变 2019 年初的"满 250 日"判定：
生产缓存从 2018-01-02 起正好 243 个交易日，本来**没有任何标的合格**；补进来之后 36 只
当天就合格，2019 年净值最多偏离 **0.79%**（实测）。也就是说它会悄悄改掉主回测的起点语义。
所以早期数据放 `data/cache_early/`，只给研究脚本用。

### 7.12 第二排序键：52 周高点距离（负结果）与扩散度为何不测

7.10 ⑧ 的结论是"alpha 只在 2023-26 有效"，于是自然会问：有没有**非共线**的信息
能在近平局处补一点？挑了两个零数据成本的候选——52 周高点距离（George-Hwang）与
行业扩散度。判据**在 `scripts/research/ab_secondary.py` 的 docstring 里跑前写定**。

复现：`python -m etfquant research ab_secondary`（`etfquant/secondary.py`，12 项单测）。

**设计：它不是"第二个因子"，是"第二排序键"**

`score = z20 + w·z_secondary`，w=0.05 时 z 值 ±2 的贡献最多 ±0.1，只能翻动
**z20 差 < 0.1** 的配对。这是 7.1/7.6/7.8 三次失败的直接结果：任何有实质权重的
第二因子都会稀释"尽快换到最强"，然后两段子区间反号。单测
`test_blend_cannot_override_a_real_gap` 钉住了这条性质——z 差 0.5 时次要因子翻不动。

**① 信号层：两个窗口同时变差**

| 权重 | 5d top3−全池 t | 5d 均值 | 20d t | 20d 均值 | 5d 分段 2019-22 / 2023-26 |
|---|---|---|---|---|---|
| 基线 | **1.57** | +29.3bp | **1.09** | +61.3bp | −2.7 / +62.5bp |
| w=0.05 | 1.20 | +21.8bp | 0.77 | +44.4bp | −0.3 / +44.8bp |
| w=0.10 | 1.05 | +19.1bp | 0.80 | +45.9bp | −4.5 / +43.5bp |

判据 ①（两个窗口 t 同时提高、且 2019-22 不下降）**不过**。共线性检查给了背景：
z(52周高点) 与 z(R20) 的横截面相关中位 **0.39**——不是同一个东西（否则不用测），
但重叠足够大，掺进来主要是噪声。

**② 回测层：又是"一段赢、一段输"**

| 权重 | 全样本 | 最大回撤 | 夏普 | 2020-22 | 2023-26 |
|---|---|---|---|---|---|
| 基线 | 17.3% | −28.9% | 0.69 | +11.5%（夏普 0.53） | +26.8%（夏普 0.90） |
| w=0.05 | 17.1% | −27.6% | 0.68 | +10.4%（夏普 **0.49**） | +27.3%（夏普 0.91） |
| w=0.10 | 17.0% | −27.6% | 0.68 | +9.7%（夏普 **0.46**） | +28.5%（夏普 **0.94**） |

判据 ②（两段夏普同时 ≥ 基线）**不过**：2020-22 单调变差（0.53→0.49→0.46），
2023-26 单调变好（0.90→0.91→0.94）。方向和 7.10 ⑧ 完全一致——
**"距新高越近越强"是个趋势确认型信号，只在趋势市有效；2020-22 那种反复反转的市场里，
它等于系统性买入"已经涨到高位"的品种。**

判据 ③（邻域一致）过了，但前两条已经否掉，按纪律不采纳。

**③ 行业扩散度：测了相关性，决定不测策略**

"同行业有多少只在涨"在**股票**上是有效宽度指标。本项目先用相关性检验它是否退化：

| 分组粒度 | 同组日均收益相关性 | 非同组 |
|---|---|---|
| 粗分类（行业/主题/跨境/宽基…） | 0.483（7,448 对） | 0.350 |
| 细分行业（半导体/医药/科技…，需手写关键词表） | **0.734**（572 对） | 0.374 |

- 粗分类下同组相关性只有 0.48，因为"行业"这一类里装的是不同行业——分组太粗，
  breadth 会变成"全市场行业 ETF 有多少在涨"，那是**时序**指标（更像闸门），
  不是横截面因子；
- 细分行业要到 0.73，但分组表得手写 20 组关键词（半导体 10 只、医药 22 只…），
  这本身就是一份人为约定，且 0.73 意味着"同组多少只上涨"基本等于"该行业的共同涨跌"，
  而这层信息 R20 已经在吃。

所以：**不测**。不是因为怕麻烦，是因为在 0.73 的相关性下，它大概率会重复 52 周高点
这条负结果的形状——趋势市有效、反转市有害，而代价是多一张手写映射表。

**④ 这两条改了什么**

1. `secondary` / `secondary_weight` 作为**默认关闭**的实验开关保留
   （与 `dedup_corr` / `vol_target` / `resid` 同类），策略文档里标注"7.12 两档全否"；
2. `docs/github_strategies.md` 的 #31/#32 标为"已测/已评估"，避免下一轮再查；
3. 结论并入 7.10 的总判断：**这套框架的 alpha 就是"尽快换到最强"，凡是"确认趋势"
   的补充信息，都会在反转市里付费**——52 周高点是最干净的一次验证。


### 7.13 元标签：让模型决定"这一期下多重的手"（负结果）

7.12 之后剩下的唯一空间不是"加因子"，而是**同一批标的、更少的手数**：
如果"什么时候不该满仓"可预测，它应该表现为回撤更浅，而不是选股更准。
这就是 López de Prado 的两层结构——一级模型选什么，二级模型只决定下多大。

复现：`python -m etfquant research ab_meta`（`etfquant/meta.py`，13 项单测）。
判据**在脚本 docstring 里跑前写定**；三条（有效性前置、三种映射同时过、训练窗口敏感）。

**设计上的三条自限**

1. **只用 3 个慢变量**：`regime` 分数、基准（沪深300）20 日年化波动、信号近 6 期胜率；
2. **走前向验证**：每个决策日只用**当日之前**已实现的标签重训（IRLS 逻辑回归，无 sklearn）；
   截断未来不改变历史预测，有单测 `test_walk_forward_is_causal`；
3. **仓位只减不增**（0.5~1.0），最坏情况是少赚，而不是把杠杆引入一个没验证过的信号。

**结果：三种映射全部跑输**

| 映射 | 减仓期数占比 | 全样本 | 最大回撤 | 夏普 | 2020-22 | 2023-26 |
|---|---|---|---|---|---|---|
| 基线 | — | 17.3% | −28.9% | **0.69** | **0.53** | **0.90** |
| threshold（≥0.6 满仓 / ≥0.45 七五折 / 否则半仓） | 62% | 13.3% | −26.5% | 0.63 | 0.50 | 0.85 |
| linear（0.5+(p−0.5)，截断 [0.5,1]） | 70% | 11.3% | −22.5% | 0.60 | 0.49 | 0.88 |
| downside（只有 p<0.45 才减半） | **3%** | 15.9% | −31.0% | 0.65 | 0.51 | 0.85 |

两段夏普同时下降，回撤虽然变浅（threshold −26.5%、linear −22.5%），但代价是年化少 4~6pp——
**夏普全跌**，说明减仓削掉的收益多于它避开的亏损。

**根因：模型根本没有区分度**

与其事后解释曲线，不如直接看预测质量：

| 指标 | 值 |
|---|---|
| 训练样本 / 有预测的期数 | 372 / 272 |
| 标签为正的比例（5 日多头组合上涨） | 53% |
| 预测概率分位 | p5 0.451 / p50 0.531 / p95 0.698 |
| **AUC** | **0.442**（0.5 = 随机；低于 0.5 = 方向还反了） |

三个特征与标签的相关系数分别是 **+0.003（regime）、+0.023（vol）、+0.007（hit）**——
基本是零。也就是说：这套框架里"下一期赚不赚"在仓位层面几乎不可预测；
模型学到的是噪声，然后把它变成一个系统性减仓的理由。

这解释了两件反直觉的事：

- **threshold 减仓 62% 的期数**：因为概率分布挤在 0.45~0.70，阈值 0.6 极少触发满仓，
  结果等于长期打七折持有——那不是择时，是降杠杆；
- **downside 只减 3% 却让回撤更差**（−31.0% vs −28.9%）：它减仓的那 3% 期数
  恰好不是危险期，属于"用噪声选出来的减仓点"。

**结论**

不采纳。`meta_exposure` 与 `secondary`、`resid`、`vol_target` 一样作为**默认关闭**开关保留。
三条外部策略对照（7.6~7.9）+ 两条自研方向（7.12 第二排序键、7.13 元标签）到这里可以收口：
**这套框架的 alpha 全部来自"尽快换到最强"，而且它在统计上只有 1.5 左右的 t 值——
在这么薄的信噪比上，任何再叠一层的模型都只会把噪声变成规则。**


### 7.14 ETF 份额（申赎）：一条只能"攒"、不能"测"的方向

`docs/github_strategies.md` 的 #70 是 72 条里唯一"数据是新的、机制清楚、且与现有因子
不共线"的方向。7.12 与 7.13 都否掉之后，这是最后一条。结论先说：**历史份额拿不到，
现在测不了；但快照每天在流失，所以先把采集做起来。**

**① 数据可得性探测（2026-10-30 实测）**

| 源 | 结果 | 能否取历史 |
|---|---|---|
| 上交所 `query.sse.com.cn` · `COMMON_SSE_ZQPZ_ETFZL_XXPL_ETFGM_SEARCH_L` | 923 只，字段 `STAT_DATE / SEC_CODE / SEC_NAME / TOT_VOL`（万份） | **否**。`tradeDate / queryDate / beginDate / txtDate / statisticsDate` 五个参数全部被忽略，`STAT_DATE` 恒为最新交易日 |
| 深交所 `szse.cn/api/report` · `CATALOGID=1945`（ETF 列表） | 768 只，字段 `dqgm`（当前规模，万份）、`sys_key`、`kzjcurl` | **否**。`txtQueryDate / txtDate` 无效，`subname` 恒为当天；`PAGENO` 可分页（每页 10 条） |
| 天天基金 `fundf10.eastmoney.com/gmbd_<code>.html` | 可访问 | **只有季度报告期**（规模变动表），不是日频 |
| 腾讯快照 `qt.gtimg.cn` | 80+ 字段 | 无份额字段 |
| 东财 `push2` 系列 | 本机不可直连（见第三章） | — |

也就是说：**日频份额序列在可达的数据源里不存在**。这不是"实现难"，是"数据没有"。

**② 所以做了什么：一个最小采集器**

`etfquant/shares.py` + `scripts/collect_shares.py`（6 项单测，全部离线，用假 payload 解析）。
`python -m etfquant shares` 跑一次；已挂在 `refresh` 末尾（**失败不阻断**回测与信号）。

首次运行（2026-10-30）：

```
[OK] 快照日期 2026-10-29, 2026-10-30；本次 1691 条，池内覆盖 260/260 只
     写入 etf_shares.csv：累计 1691 行 / 2 个交易日
```

两个细节值得记下来：

- **上交所比深交所晚一天**（T+1 披露），所以同一次采集里两边的 `STAT_DATE` 不同 →
  入库用的是**交易所返回的日期**，不是本机日期。否则会把"昨天上交所的份额"记成今天，
  将来做变化率时凭空多出一个 100% 的假跳变。
- **单位都是万份**，用 510300（4,545,678.90 万份 ≈ 45.5 亿份）与 159915 的
  市值/净值量级反算核对过。`"-"` 与空值一律当缺失，不当 0——0 会伪造"赎回 100%"。

**③ 将来怎么测（判据先写在这里，等数据够了直接用）**

满 **120 个交易日**（约半年）后：

1. 因子：`flow_z = z(过去 20 日份额对数变化)`，同日横截面标准化；
2. 检验：5 日 forward return 的 rank IC（Newey-West t）与 Q9−Q0 价差；
3. 采纳条件：**|t| > 2 且 Q9−Q0 与 IC 同号**，同时方向必须是"份额增加 → 后续偏强"
   （资金流入的解释）；若方向相反，视为"散户追高"效应，需要独立机制才考虑，不直接反转用。

注意这条与前六条不同：它**没有历史可回测，只有前向**。所以它天然绕过了 7.5 的
多重检验问题（只测一次），但也意味着**必须等**——这正是它到现在还没结论的原因。


### 7.15 外部验证：除了我们自己，还有什么能证明这是对的

前十四节都在用**同一份历史**反复检验同一个策略。这节换一个问题：
**如果所有结论都是我们两个（人和 AI）在自说自话，外部有什么能推翻或支持它？**

**一、四类证据，按"能否被第三方独立检查"排序**

| 类别 | 是什么 | 我们现在有什么 | 缺什么 |
|---|---|---|---|
| **随机化** | 把"选股"换成随机抽签，看真实策略在零分布里的位置 | **本节做完**：300 组对照 | — |
| **时间** | 未来数据，不可回填、不可调参 | 信号归档 + 月报，20 期（真实 1 期） | 时间本身；且 alpha 显著需约 200 个月 |
| **空间** | 同一规则换一个市场，机制为真应同向 | 港股 ETF 实测可取（`hk02800` / `hk03033`，3 个月窗口 61 根）；美股 `usSPY/usXLK` 取不到 | 需另建港股票池 —— 这是下一步，不是本节 |
| **他人** | 任何人用同一份数据跑出同一个数 | 确定性 tie-break、原子写、全套单测（见 `tests/`）、审计 23 项 | **复现清单（hash manifest）**、**预注册文档** |

**二、随机对照怎么做的**

同候选集（**含策略自己的趋势与量比过滤**）、同调仓日、同权益敞口路径、同费率；
唯一的差别是"3 只是 R20 排出来的，还是随机抽的"。抽 300 组，不许重复抽同一只。

| 指标 | 实际 | 随机中位 | 随机 p95 | 实际分位 |
|---|---|---|---|---|
| 毛 CAGR（权益腿 × 闸门） | **18.6%** | 12.4% | 17.9% | **97%** |
| 净 CAGR（各扣各自换手） | **16.2%** | 2.4% | 7.9% | **100%** |
| 夏普 | **0.75** | 0.71 | 0.96 | **60%** |

参考点：全池等权（每期持有全部候选）× 同一条闸门 = 毛 CAGR 4.3%、夏普 0.34；
随机 300 组的均值也是 4.3%——**抽签是无偏的**，这一点先自证了。

**三、这张表推翻了我十分钟前的结论**

第一版跑出来是"实际 18.6%、随机中位 4.2%、100 分位"，看上去选股贡献 **14pp/年**。
但那版**漏了趋势与量比过滤**：实际组在"已在 60 日线上方、量比正常"的池子里选，
随机组在"全部可交易标的"里抽。它测的是"**要不要做趋势过滤**"，不是"选哪 3 只"。
补上过滤后随机中位从 4.2% 升到 12.4%，差距从 14pp 缩到 6pp。

真正刺眼的是最后一行：**夏普分位只有 60%**。拆开看：

- 毛收益的 97 分位，来自"趋势过滤 + 挑最强"这套**组合**；
- 但风险调整之后，"挑最强 3 只"这一步几乎**没有增量**——它把收益抬高，也把波动同比例抬高；
- 净收益的 100 分位主要来自**换手纪律**：随机组年换手 100 倍（成本 10%/年），
  我们 24 倍（2.4%/年）。这一条差异，比"选股"大得多。

与 7.10（α t=1.38）、7.12（第二排序键无效）、7.13（元标签 AUC 0.44）完全一致：
**这套系统里真正在起作用的不是"选股模型"，而是"趋势过滤 + 闸门 + 低换手"三件工程上的事。**

**四、所以，什么能证明它是对的**

诚实地说：**目前没有一件能独立证明。** 四类的实际状态是——

- **随机对照**：已做，结论是"选股不显著、工程有效"。它的作用是**证明弱**，这正是它该做的事；
- **时间**：只有 1 期真实前向。要等，而且 7.10 已经算过，等 200 个月才能"证明 alpha 存在"；
- **空间**：可行（港股数据可达）但未做；
- **他人**：机制齐备，但**没有复现清单**——别人无法用手上的东西验证"17.32% 是这份数据算出来的"。

**五、顶尖专家会做、而我还没做的四件事**

1. **复现清单（manifest）**：把输入（`etf_pool.csv` + 260 个缓存文件的 SHA256）、
   代码状态、输出（`nav_main.csv` / `perf_main.csv` 的 hash）写进 `output/manifest.json`，
   `audit` 校验。这样"别人能不能算出同一个数"从口号变成一条命令。
2. **预注册文档**：把前向验证的判据写成**带时间戳、不再修改**的文件，
   而不是月报里可以随手改的一段规则。这是唯一能防止我们事后修改标准的机制。
3. **试验登记簿 + DSR 重算**：7.5 的 DSR 是按当时的试验次数算的；之后 7.6~7.15
   又做了十次实验，**多重检验预算已经变了**。不登记试验次数，DSR 就是自欺。
4. **港股 transfer test**：同一套规则搬到港股票池。若"追最强 + 闸门"在另一个市场
   也给出同向的风险调整改善，才说明它不是 A 股 2019-2026 的拟合。

**六、这节改变了什么**

它没让策略变好，它让**我们对它的判断更准**：收益的 97 分位由工程构件撑着，
选股的夏普分位只有 60%。如果还要继续投入，方向不是"再找一个因子"，
而是把上面 1、2、3 做完——它们决定的是"这个数字能不能被别人相信"，
不是"这个数字能不能更大"。


### 7.16 外部验证三件套：DSR 重算、复现清单、预注册

7.15 说"外部能证明它的只有四样，随机化已做，其余三样缺"。这一节把缺的三样补齐，
顺带解决一个更早的问题：**7.5 的 DSR 用的是拍脑袋的 N=60。**

**① Deflated Sharpe 重算（试验登记簿驱动）**

`data/trials.json` 登记了 10 次挑选性实验、共 **68 个变体**（含 29 个参数网格；
7.15 的 300 组随机对照是零分布，不算）。`python -m etfquant dsr` 用它重算：

| 假设 | N | 临界 Sharpe | 实际 | DSR |
|---|---|---|---|---|
| 不搜索 | 1 | 0.00 | 0.69 | 97.1% |
| 只算参数网格 | 29 | 0.19 | 0.69 | 91.7% |
| 计入登记的全部试验 | 68 | 0.22 | 0.69 | 90.4% |
| **保守方差（σ=0.5）** | 68 | **1.20** | 0.69 | **8.3%** |

**这张表的诚实之处不在某个数字，而在最后一行。** 网格的 29 个变体是近邻参数，
日频 Sharpe 方差只有 3e-5，所以临界 Sharpe 只有 0.19，DSR 显得稳健。但一旦把
68 次试验当作**彼此独立**的尝试（Sharpe 离散用 σ=0.5 的保守假设），DSR 崩到 8.3%。
**结论取决于"这些试验有多独立"这个假设，而不是 N 本身**——登记簿的价值是让这个
敏感性可见，而不是再给出一个看似权威的单一数字。

**② 复现清单（manifest）**

`python -m etfquant manifest` 把 261 个缓存文件 + 池文件 + 5 个关键产物的 SHA256
写进 `output/manifest.json`，并给出一个总指纹。任何人拿到同一份 `data/` 与 `output/`，
能复现同一指纹——"17.32% 是这份数据算出来的"从此可验证。`audit` 每次都会复核。

**③ 预注册（`docs/pre_registration.md`）**

写死了前向验证的判据与**停止条件**（累计残差 < −10pp、36 个月未转正、
连续 3 季偏差 > 0.5pp），以及"不因前向数据回头调参"。文件的 SHA256 存于
`data/pre_registration.sha256`，`audit` 校验——改动文档而不改 hash 会报警。

**这三样加起来改了什么**

没让策略好一分钱。它们做的是同一件事：**把"17.32% 该不该信、信多少"从情绪变成
可执行的校验**。DSR 90.4%（网格口径）到 8.3%（独立口径）这个区间，就是目前最诚实
的答案——这也是为什么对外口径一直是 11%~13%，而不是 17%。


## 七点四、已知数据风险

**缓存新鲜度**。下载脚本原先用「最后交易日距今 10 天内即视为最新」判定缓存命中，
导致 260 只标的里有 20 只长期落后 1 个交易日（含基准沪深300），信号里的参考价用的是前一日收盘。
现已改为用实时快照推出全市场最新交易日、只补抓缺失尾部；`scripts/audit.py` 的 F 段会逐只校验。

**交易日历**。执行日只跳过周末，**不跳过法定节假日**。遇到长假请以交易所实际开市日为准。

## 七点五、换手成本（重要）

本策略每 5 个交易日调仓一次，**年均单边换手约 24 倍**，意味着每年要付出约
**`换手 × 2 × 0.10% = 4.8%`** 的摩擦成本。这是收益的最大漏损来源：

- 消融实验显示，仅"排名缓冲带"一项就能把换手从 28.9 倍压到 24.1 倍；
- 把调仓周期放宽到 10 日，换手降到 16 倍、成本降到 3.2%，但 CAGR 也从 17.3% 掉到 13.8%；
- 也就是说，**提高调仓频率带来的 alpha 与增加的交易成本几乎相互抵消**。

若按实盘更保守的 0.15% 单边成本估算，年化成本将升至 7.2%，CAGR 还要再降约 2.5pct。
这是评估该策略时必须打上的折扣。

## 八、已知局限

1. **样本内优化偏差**。参数基于同一段数据选定，虽有消融与子样本检验，仍无法排除对 2023-2026 结构性行情的拟合。真实样本外表现应显著低于 17.3%。
2. **幸存者偏差**。标的池为当前在市 ETF，清盘基金未纳入。
3. **跨境 ETF 敞口错配（已知缺陷）**。闸门以沪深300 判断市场状态，但池内含 62 只跨境 ETF 与 4 只商品 ETF。当 A 股弱、美股强时，跨境品种仓位会被误砍。实盘应改为按资产类别分别判定。
4. **无盘中执行建模**。假设 T+1 开盘价全额成交；跨境 ETF 存在溢价与 T+2 交收差异。
5. **容量约束**。Top3 集中持仓 + 中小主题 ETF 流动性有限，容量估计在数亿元量级。
6. **参数敏感性**。调仓周期从 5 日改到 10 日，CAGR 从 17.3% 掉到 13.8%；
   调仓频率扫描（2/3/5/10/20 日）还出现非单调（3 日 12.2% 低于 2 日 16.3% 与 5 日 17.3%），
   说明**单点参数的排名本身带噪声**，17.3% 这个数字含参数选择运气。
7. ~~**日更信号与 5 日调仓口径不一致**~~（2026-10-29 已修）。`run_signal.py` 原先取
   "数据最后一个交易日"重算目标，连续三天运行会得到三份不同持仓（10-26 地产 /
   10-27 红利低波 / 10-28 纳指ETF），照做等于每天换仓。「实盘跟踪」的 −0.39pp 偏差就是这么来的。
   现在信号钉在最近一个调仓日（`etfquant/rebalance.py`），界面显示
   「调仓决策 → 开盘买入 → 下次换仓」三个日期，中间几天打开内容不变；归档也按调仓日
   整体替换，不再每天新增一期。
8. **回填期与 live 期不可等价看待**。`scripts/backfill_archive.py` 用**当前**策略回放历史，
   而 `live` 是当日真实输出。策略或池子一旦调整，回填会跟着变、live 不会——这正是
   「实盘跟踪」存在的意义，但也意味着**回填期不能当作业绩证据**。
9. **样本内实验已接近耗尽，且已量化**。至 2026-10 已在同一段历史上试过约 60 组变体。
   「7.5 过拟合体检」给出三个数：PBO **43.2%**（挑冠军有 43.2% 概率挑到噪声）、
   滚动重挑参数比固定默认**差 2.8pp/年**（12.62% vs 15.41%）、样本内→样本外 Sharpe
   **衰减 26%**。因此 17.45% 应视为上限，对外口径用 **11%~13%**；继续调参的期望收益已低于过拟合风险。
   下一步只能做前向验证（记录每日信号并复盘），不能继续在同一段历史上找参数。
10. **机会集本身在扩张（2026-10-30 补充）**。回测区间的横截面不是恒定的：
    2019 年初可选 ETF 只有 **40 只**，2021 年初 80 只，2022 年初 127 只，2024 年初 195 只，
    2026 年初 254 只。策略的 alpha 来自"从一堆主题里挑最强的三个"——**可选主题的数量
    本身就是策略的一部分**，而它在样本期内翻了两番。这意味着：
    ① 2023-26 段的超额有一部分来自"选择集变宽"，不完全是行情或策略能力，
       对未来外推要打折（ETF 数量不会再翻两番）；
    ② 回测起点再往前（2016-2018 横截面仅 30~40 只且幸存者偏差更重），
       测的就不是"这个策略"，因此主区间以 2019-01 为下限是**结构性约束**，
       不是任意选择；更早的历史只适合做压力测试附录，不进主区间。

## 九、目录结构

> 脚本索引见 [`scripts/README.md`](scripts/README.md)；产物契约见 [`output/README.md`](output/README.md)。

```
etf-quant/
├── AGENTS.md           给 AI Agent 的项目入口（一页纸：命令 / 地图 / 硬约束）
├── README.md           本文（结论、实验、已知局限）
├── docs/
│   ├── architecture.md   分层与扩展指南
│   ├── strategy_dd.md    外部策略尽调清单（五道闸门 / 红旗 / 协议）
│   ├── github_strategies.md  GitHub 开源策略目录（72 条 + 可迁移性评估）
│   └── code_review.md    代码评审记录
├── 打开界面.bat       双击打开 Web 控制台（推荐）
├── launcher.py         终端交互式菜单
├── server.py           Web 服务（API + 任务管理 + 静态托管，零额外依赖）
├── web/ mobile/ android/ dist/   控制台 / App 前端 / 打包工程 / APK
├── etfquant/           核心库（依赖方向只能向下）
│   ├── datafeed.py       腾讯行情（快照 + 前复权日线，含收盘判定与限速）
│   ├── universe.py       扫描 / 分类 / 去重 / 池构建
│   ├── pipeline.py       面板装配（Panel）
│   ├── factors.py        因子库（动量 / 波动 / 趋势 / 量比 / 横截面标准化）
│   ├── strategy.py       4 个策略（TGAR 为默认主线）
│   ├── backtest.py       事件驱动引擎（T+1 开盘、双边成本、权重漂移）
│   ├── metrics.py        绩效指标
│   ├── rebalance.py      调仓日历（决策日 / 买入日 / 下次换仓）
│   ├── track.py          信号归档与纸上净值
│   ├── holdings.py       实盘持仓
│   ├── expectation.py    对外口径（11%~13% 的唯一换算处）
│   ├── overfit.py        过拟合检验（CSCV / DSR / 滚动前向）
│   ├── report.py         SVG 图表与 HTML 渲染
│   └── research 模块     dual_mom / resid_mom / macross / chan / monthly（只被研究脚本调用）
├── scripts/            日常流程（16 个）+ README 索引
│   ├── download_history.py / run_backtest.py / run_signal.py / make_report.py
│   ├── ablation.py / grid2.py        界面「效果验证」页的数据源
│   └── research/       一次性实验（11 个），产物进 output/experiments/
├── tests/              266 项单元测试
├── output/             产物（顶层=应用依赖，experiments/=可删）
└── data/               行情缓存、标的池、信号归档
```

命令行统一入口（人与 Agent 同一套）：

```bash
python -m etfquant doctor      # 数据截止日 + 绩效 + 口径
python -m etfquant refresh     # 更新行情 → 回测 → 信号（= 界面按钮）
python -m etfquant research    # 列出一次性实验脚本
```
